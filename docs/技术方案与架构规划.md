# Nooj Log 技术方案与架构规划

> 版本：v2.1 ｜ 日期：2026-10-22
> 适用环境：阿里云 ECS 2 vCPU / 2 GiB ｜ Ubuntu ｜ 1Panel v2 ｜ 与现有 ymao.me 同机
>
> **v2 变更**：放弃 Next.js 静态导出方案，改为复用 ymao.me（Markdown-i）已验证的 **Hono + SQLite + esbuild** 架构。
> 读者页由 Node 服务端渲染首帧，内容发布**不再触发任何构建**；只有改代码时才用 esbuild 重新打包，耗时数秒。
>
> **v2.1 变更**：改为**单域名** `nooj.cn`，取消 `admin.nooj.cn`；后台走同域单段秘密路径（默认 `/admin`，上线前改随机串），只需一个 OpenResty 站点与一张证书。

---

## 0. 结论摘要

| 维度 | 决策 |
| --- | --- |
| 代码基础 | 复用 Markdown-i（ymao.me）的 Hono 应用骨架、SQLite 适配层、后台与主题系统 |
| 运行时 | Node.js 22/24 + Hono 4 + better-sqlite3，单进程 |
| 构建 | esbuild 打包为单文件 `dist/server.mjs`，仅代码变更时执行，秒级、低内存 |
| 内容发布 | **零构建**：写 SQLite + 失效缓存，刷新即生效 |
| 前台 | 服务端渲染首帧 + 现有 `app.js` 接管，新增 `nooj` 主题包 |
| 后台 | 复用现有后台，入口改为单域名单段秘密路径，新增项目、标签、文章类型管理 |
| 数据库 | 独立 SQLite（WAL），与 ymao.me 完全隔离 |
| 部署 | 新增 1Panel Node 容器（端口 3001）+ OpenResty 反代；与 8787 并存 |
| 新增模块 | `projects` 表与页面、`/archive`、`/tags/:slug`、Nooj 主题 |
| 稳态内存 | nooj 新增约 60–120 MB；整机（含 ymao.me）约 750–950 MB / 2048 MB |
| 主要取舍 | 读者页依赖 Node；用 OpenResty 微缓存 + stale 兜底降低故障影响 |

一句话：**沿用 ymao.me 的成熟链路，发文不构建、部署不变、内存不高；Nooj 主要是一套新主题、新信息架构和一个项目模块。**

---

## 1. 为什么改

检查 ymao.me 后的关键事实：

| 项 | ymao.me 实际 |
| --- | --- |
| 框架 | Hono 4 + TypeScript |
| 数据 | better-sqlite3（D1 风格适配层） |
| 构建 | esbuild → `dist/server.mjs`，单文件 **568 KB** |
| 运行时依赖 | 仅 4 个：hono、@hono/node-server、better-sqlite3、node-cron |
| 渲染 | SSR 首帧 + `public/app.js` 单页应用接管 |
| 部署 | 1Panel Node 容器（8787）+ OpenResty 反代 |
| 发布文章 | **不构建**，内容实时从 SQLite 读取 |
| 服务器构建 | 容器内 `npm ci && npm run build`，esbuild 几秒完成、内存几十 MB |

因此：

- 之前担心的“服务器构建内存不够”，只针对 **Next.js 构建**；esbuild 没有这个问题。
- 之前设计的“每次发文触发静态重建”，是纯静态方案的代价，不是必需。Nooj 采用 SSR 后，**发文、改主题配色、审核友链都不需要构建**。
- 继续引入 Next.js 会多出 monorepo、快照接口、Pagefind、GitHub Actions、静态发布与回滚等一整套链路，与现有基础设施重复。

## 3. 总体架构

### 3.1 拓扑

```
                        ┌──────────────────────────────┐
                        │       阿里云 ECS 2C2G         │
                        │                              │
读者 ──HTTPS──► 1Panel OpenResty（容器，80/443）        │
                        │   └─ nooj.cn（单域名）        │
                        │        ├─ /             → nooj Node 容器 3001
                        │        ├─ /api/*        → nooj Node 容器 3001
                        │        ├─ /media/*      → nooj Node 容器 3001
                        │        └─ /<后台秘密路径> → 同一容器，禁缓存
                        │                              │
                        │  nooj 容器（3001）            │
                        │    ├─ Hono SSR + app.js      │
                        │    ├─ SQLite（WAL，外挂卷）   │
                        │    └─ 本地媒体 / R2 / B2      │
                        │                              │
                        │  ymao.me 容器（8787，现状）   │
                        │  blog-radar 容器（8899）      │
                        └──────────────────────────────┘
```

### 3.2 请求链路

**读者页**

```
浏览器 → OpenResty → nooj Node（3001）
                       ├─ Hono 查 SQLite
                       ├─ 渲染首帧 HTML（标题、正文、列表）
                       └─ 返回 HTML + app.js
浏览器执行 app.js → 接管路由；评论/点赞等再走 /api/*
```

- 首帧 HTML 由服务端直出，SEO 与首屏可见性不依赖 JS。
- 客户端导航由 `app.js` 的 `route()` 接管，切换页面不整页刷新。
- 评论、点赞、搜索建议走 JSON API。

**发布文章**

```
后台保存 → SQLite 写入 → 失效进程内缓存 → 完成
```

- 没有构建、没有静态文件切换、没有 GitHub Actions。
- 读者刷新即可看到新内容；OpenResty 若开启 3–5 秒微缓存，最迟 5 秒后可见。

**修改主题**

- 改配色/配置：写 `site_config`，刷新生效，不构建。
- 改 `themes/nooj/style.css` / `theme.js`：scp 上传静态文件，更新版本号，不重新打包服务端。
- 只有改 `src/` 下的服务端代码，才需要 esbuild 构建并重启容器。

### 3.3 域名与端口

| 域名 | 用途 | 说明 |
| --- | --- | --- |
| `nooj.cn` | 读者站 + 公开 API + 后台 | 唯一域名，一个 OpenResty 站点、一张证书 |
| `www.nooj.cn` | 301 → `https://nooj.cn` | 保留路径与查询串 |
| `img.nooj.cn` | 可选，媒体域名 | 用本地磁盘时可不需要 |

- 后台入口：`nooj.cn/<后台秘密路径>`，由 `site_config` 配置，默认 `/admin`；建议首次部署后改为单段随机路径（如 `/admin-8f3k2`），改完立即生效，无需重启。
- 公开访问 `/admin` 一律返回 404，秘密路径才进入后台；秘密路径不写入 `robots.txt`，也不出现在任何页面链接中。
- 不再需要 `admin.nooj.cn`：后台与前台同域，Cookie 天然同源，省掉第二个证书与站点配置。

| 端口 | 用途 |
| --- | --- |
| 80 / 443 | OpenResty |
| 3001 | nooj Node 容器（仅内网） |
| 8787 | ymao.me（现状，不动） |
| 8899 | blog-radar（现状，不动） |

### 3.4 目录布局

```
/opt/1panel/www/sites/nooj.cn/
├── index/                  # 代码与静态资源
│   ├── src/
│   ├── public/
│   │   └── themes/nooj/    # Nooj 主题
│   ├── dist/server.mjs     # esbuild 产物
│   ├── data/               # 外挂到容器
│   │   ├── nooj.db
│   │   └── media/
│   └── logs/
└── backups/
```

- `data/` 必须外挂到容器，容器重建不丢数据。
- 与 ymao.me 的 `/opt/1panel/www/sites/ymao.me/index/data/markdown-i.db` 完全分开。

## 4. 信息架构

### 4.1 导航

主导航五项：**首页 / 文章 / 项目 / 动态 / 关于**

次级入口：归档、标签、友链、搜索、RSS（页脚与文章页）。

### 4.2 URL

| 路径 | 渲染方式 | 说明 |
| --- | --- | --- |
| `/` | SSR | 首页 |
| `/posts` | SSR | 全部文章，支持 `?type=` |
| `/posts/type/:type` | SSR | 开发/生活/笔记 |
| `/post/:slug` | SSR | 沿用现有文章详情路径 |
| `/archive` | SSR（新增） | 按年份归档 |
| `/tags` | SSR（新增） | 标签索引 |
| `/tags/:slug` | SSR（新增） | 标签归档 |
| `/projects` | SSR（新增） | 项目列表 |
| `/projects/:slug` | SSR（新增） | 项目详情 |
| `/moments` | SSR 首帧 + SPA | 动态列表 |
| `/about` | SSR | 关于 |
| `/links` | SSR | 友链 + 申请 |
| `/search` | SPA | 调 `/api/search` |
| `/<后台秘密路径>` | 后台 | 单域名单段秘密路径，默认 `/admin` 应屏蔽，仅站长知晓 |
| `/rss.xml`、`/sitemap.xml`、`/robots.txt` | 动态生成 | 复用现有 SEO 模块 |

> 文章详情路径沿用 ymao.me 的 `/post/:slug`，避免改动现有路由与前端。若必须使用 `/posts/:slug`，需同时处理旧链接 301。

### 4.3 内容模型

| 实体 | 字段 |
| --- | --- |
| Post | slug、title、excerpt、content_md、cover、status、type、tags[]、featured、pinned、project_id |
| Project | slug、name、tagline、content_md、cover、stack[]、repo_url、demo_url、status、started_at、ended_at、featured、sort_order |
| Moment | content、images[]、video、location、created_at |
| Comment | target_type（post/moment）、target_id、parent_id、nickname、content、email、website、avatar |
| Friend | name、url、avatar、description、status、sort |
| SiteConfig | 站点名、slogan、导航、社交、主题、主题配置、SEO、存储配置 |

分类体系：`type` 三值 + `tags` JSON 数组，不建独立分类表。标签页通过 SQLite `json_each` 查询，千篇文章规模足够。

## 5. 页面模块与布局

### 5.1 全局框架

- 容器 1120 px，移动端左右 20 px。
- Header 64 px 吸顶，纸底 + 1 px 底描边；桌面五项导航，移动端抽屉。
- 当前导航项底部 2 px 鼠尾草绿短横线（宽 20）。
- Footer 浅底、上下 48 px、三列（简介 / 导航 / 联系），底行含备案与构建信息。
- 所有页面共享跳转链接、焦点环、`prefers-reduced-motion`。

### 5.2 首页 `/`

| 顺序 | 模块 | 要点 |
| --- | --- | --- |
| 1 | Hero | 72 px 头像、站名 44/54、slogan 20/32、两行简介、社交图标、状态胶囊 |
| 2 | 精选项目 | 3 列卡片（≥900），16:9 封面、状态角标、技术栈胶囊 |
| 3 | 最新文章 | 2 列卡片流，类型胶囊、标题、两行摘要、日期·阅读时长·标签 |
| 4 | 最近动态 | 3 条时间线，最多 3 张缩略图、点赞/评论数 |
| 5 | 页脚 | 全局 Footer |

- 模块间距 64–80 px，卡片内 24 px。
- 无内容区块整块不渲染。
- 数据在 SSR 时一次查询完成，避免 N+1。

### 5.3 文章列表 `/posts`

- 页头：H1“文章”28/40 + 总篇数 + 一行简介。
- 类型切换：全部 / 开发折腾 / 生活日常 / 碎片笔记，链接到 `/posts` 与 `/posts/type/:type`。
- 高频标签胶囊（最多 12 个）。
- 2 列卡片（≥900），移动端 1 列；每页 10 篇。
- 分页 32×32 数字按钮，当前页主色浅底。
- 空状态：40 px 线性图标 + “这个分类还没有文章”。

### 5.4 文章详情 `/post/:slug`

- 面包屑 → 类型胶囊 → H1 34/46 → 日期/阅读时长/标签 → 1 px 分隔线。
- 可选封面 1120 × 21:9，固定宽高。
- 正文 720 px；桌面右侧 240 px 目录，sticky `top: 88px`；移动端折叠 `<details>`。
- 正文 17/30；H2 24/36、H3 20/32；引用块左 3 px；表格浅底表头。
- 代码块：沿用现有 Markdown 渲染；若客户端高亮库已在 `app.js` 中，则复用主题配色，不新增依赖。
- 文末：标签、复制链接、上一篇/下一篇、相关文章 3 篇。
- 评论区：构建期不需要；SSR 输出首屏评论（或由客户端拉取），提交后乐观提示。
- SEO：`BlogPosting` + `BreadcrumbList` JSON-LD。

### 5.5 归档 `/archive`

- H1“归档”+ 总篇数。
- 桌面左侧年份 sticky（96 px），右侧按年分组行列表；行高 44 px。
- 日期 13 px 等宽数字、标题 15 px、类型圆点。
- 移动端年份作为分组标题。
- SSR 一次查询按年分组，零额外接口。

### 5.6 标签 `/tags` 与 `/tags/:slug`

- 索引页：标签胶囊按文章数降序，统一字号，不做字号云。
- 详情页：H1“标签：{name}”+ 篇数 + 紧凑行列表。
- SQLite 用 `json_each(posts.tags)` 查询；标签重命名时保留旧 slug 的 301。

### 5.7 项目 `/projects` 与 `/projects/:slug`

**列表页**

- H1“项目”+ 一句说明。
- 状态筛选：全部 / 活跃 / 维护中 / 归档；无 JS 时仍显示全部。
- 2 列卡片，16:9 封面，状态角标。
- 内容：名称、tagline、技术栈胶囊（最多 4 + “+N”）、仓库/演示图标。
- 排序：精选优先 → `sort_order` → 更新时间。

**详情页**

- 封面 1120 × 21:9。
- 标题区 H1 34/46 + tagline。
- 正文 720 + 右侧 240 信息栏：状态、起止时间、角色、技术栈、仓库、演示、关联文章。
- 正文结构建议：背景、目标、实现、踩坑、结果。
- 尾部相关文章 3 篇 + 返回项目列表。

### 5.8 动态 `/moments`

- 时间线：1 px 竖线 + 6 px 圆点。
- 每条：时间、正文 15/26、最多 9 图（3 列，间距 8，圆角 10）、心情、点赞、评论数。
- 灯箱：遮罩 `rgba(30,26,22,.92)`，56 px 圆形按钮，32 px 线性关闭，Lucide 图标，中文提示。
- 点赞：静态计数由 SSR 输出，点击走 `/api/moments/:id/like`，失败回滚。
- 首页只展示最近 3 条。

### 5.9 关于 `/about`

- 96 px 头像（使用用户提供图片）、姓名、一句话、社交。
- “我在做什么”段落。
- 技能/工具分组胶囊。
- 折腾时间线（年份 + 事件）。
- 关于本站：技术栈、建站时间、更新频率。
- 联系方式：邮箱、GitHub、RSS。
- 正文宽 760，单栏。

### 5.10 友链 `/links`

- 3 列卡片（≥900），2 列（640–900），1 列移动端。
- 卡片：40 px 头像、名称、两行描述、外链箭头。
- 申请表单：名称、网址、头像、描述、邮箱；蜜罐 + 时间戳 + 限流；提交后“已提交，审核后展示”。

### 5.11 搜索 `/search`

- 复用现有 `/api/search` 与前端搜索视图。
- 输入框 48 px，结果标题主色、摘要命中高亮。
- 中文界面；无结果与空索引状态友好提示。

### 5.12 404

- 72 px “404”、一句解释、返回首页 / 去搜索。

### 5.13 后台

- 复用现有 `/admin`：概览、文章、动态、评论、友链、外观、设置、媒体。
- 新增：
  - 文章编辑增加“类型 / 标签 / 精选 / 关联项目”。
  - 项目管理：列表 + 抽屉表单（名称、slug、简介、详情、封面、技术栈、仓库、演示、状态、排序、精选）。
  - 标签管理：可从文章标签自动汇总，支持重命名。
- 后台 UI 沿用现有风格，逐步替换为 Nooj 纸感配色。

## 8. 性能与资源

### 8.1 发布零构建

| 操作 | 是否需要构建 |
| --- | --- |
| 发布/修改/删除文章 | 否 |
| 发布项目、动态 | 否 |
| 审核评论、友链 | 否 |
| 改主题配色/配置 | 否 |
| 改主题 CSS/JS | 否（只传静态文件） |
| 改 `src/` 服务端代码 | 是（esbuild，秒级） |

### 8.2 SSR 性能

- Hono + better-sqlite3 同步查询，列表页通常 1–5 ms。
- 首页/列表页一次查询取足数据，避免 N+1。
- 进程内缓存：站点配置、导航、标签计数，TTL 60 秒；写操作后失效。
- OpenResty 微缓存（仅匿名 GET HTML）：

```nginx
proxy_cache_path /var/cache/nginx/nooj levels=1:2 keys_zone=nooj:20m
                 max_size=200m inactive=10m use_temp_path=off;

location / {
    proxy_cache nooj;
    proxy_cache_valid 200 3s;
    proxy_cache_use_stale error timeout updating http_500 http_502 http_503 http_504;
    proxy_cache_background_update on;
    proxy_cache_lock on;
    proxy_cache_bypass $cookie_nooj_session;   # 带后台会话的请求不走缓存
    proxy_no_cache     $cookie_nooj_session;
    add_header X-Cache-Status $upstream_cache_status;
    proxy_pass http://nooj_node;
}

# 后台秘密路径：同域名单独 location，关闭缓存
location ^~ /admin-8f3k2 {
    proxy_cache off;
    proxy_no_cache 1;
    add_header X-Robots-Tag "noindex, nofollow" always;
    proxy_pass http://nooj_node;
}
```

- 效果：热门页面 3 秒内直接由 OpenResty 返回；Node 重启或短暂故障时，10 分钟内继续返回旧页面。
- 后台与写操作不缓存：同域名的后台秘密路径单独 `location`，`proxy_cache off`；同时 Node 对后台响应固定发送 `Cache-Control: no-store`。
- 修改后台秘密路径时，需同步改这一行 `location`（只有一处）；公开访问 `/admin` 由 Node 直接返回 404，Nginx 不参与判断。

### 8.3 内存预算（与 ymao.me 同机）

| 组件 | 典型 RSS |
| --- | --- |
| Ubuntu + sshd + cron | 150–200 MB |
| 1Panel 面板 + 监控 | 120–180 MB |
| Docker daemon | 80–120 MB |
| OpenResty | 30–50 MB |
| ymao.me Node 容器 | 60–120 MB |
| blog-radar 容器 | 40–80 MB |
| **nooj Node 容器** | **60–120 MB** |
| 其他缓冲 | 40–60 MB |
| **合计** | **约 750–950 MB / 2048 MB** |

- esbuild 构建峰值约 50–100 MB，可忽略。

### 8.4 前端资产

现状：`app.js` 679 KB、`style.css` 201 KB（未压缩），`index.html` 17 KB。gzip 后首屏 JS 约 150–200 KB。

## 10. 安全与降级

### 10.1 安全

| 面 | 措施 |
| --- | --- |
| 后台入口 | 单域名单段秘密路径 + 强密码 + 登录限流（复用 `login_attempts`） |
| 默认路径 | 公开访问 `/admin` 直接 404，不暴露秘密路径 |
| 后台响应 | `Cache-Control: no-store` + `X-Robots-Tag: noindex`，Nginx 该路径禁缓存 |
| 评论 | 蜜罐 + 时间戳 + `comment_rate` 限流 + `blocked_ips` |
| 上传 | 限制 MIME/大小；媒体 key 随机；不执行上传文件 |
| XSS | 复用现有 Markdown 清洗；评论纯文本 |
| SQL | 参数化查询；禁止拼接 |
| 限流 | OpenResty `limit_req` + 应用层业务计数 |
| 备份 | 数据库与配置 600 权限；备份独立目录 |
| 暴露面 | 仅 80/443 公网；3001/8787 仅内网 |

### 10.2 单域名后台隔离

单域名下前台公开、后台私密，靠四层叠加，不依赖子域：

1. **路径保密**：后台入口为单段随机路径，存于 `site_config`；默认 `/admin` 直接 404。秘密路径不写入 `robots.txt`、sitemap、导航或任何公开页面，也不在日志以外的响应中出现。
2. **Cookie 收窄**：会话 Cookie `nooj_session` 设 `Path=/<秘密路径>`、`HttpOnly`、`Secure`、`SameSite=Strict`，浏览器不会把它带到公开页面或 `/api/*` 请求。
3. **响应禁缓存**：Node 对后台页面与 `/api/admin/*` 固定发 `Cache-Control: no-store`；OpenResty 对该路径 `proxy_cache off`，避免后台响应进入共享缓存被他人命中。
4. **第二道门（可选）**：后台路径加 Nginx `allow/deny` 限定常用 IP，或 `auth_basic`。家庭宽带 IP 变动时用 Basic Auth 更稳。

> 同域下后台与前台共用 Origin，写操作仍必须校验 `Origin` 头防 CSRF；`SameSite=Strict` 已覆盖绝大多数场景，但服务端校验不可省。

### 10.3 降级

| 故障 | 影响 | 处理 |
| --- | --- | --- |
| nooj Node 崩溃 | 页面可能 502 | 1Panel 自动重启；OpenResty stale 缓存兜底 10 分钟 |
| SQLite 损坏 | 页面报错 | 停止容器 → 恢复备份 → `quick_check` |
| 媒体磁盘满 | 上传失败 | 日志轮转、媒体清理、扩容 |
| OpenResty 配置错误 | 全站不可用 | `openresty -t` 校验；保留上一份配置 |
| ECS 整体故障 | 全站不可用 | 每日备份 + DNS TTL 300；RTO ≈ 30 分钟 |

> 与 v1 的纯静态方案不同，SSR 方案无法做到“后端全挂仍可读”。本方案用 **OpenResty 微缓存 + stale 兜底 + 自动重启** 把影响压到“最多 10 分钟内看到旧页面”，换取发布零构建与更低资源。
